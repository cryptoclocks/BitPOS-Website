The model chooses.The server decides.

Meta's models do real work in the shop, inside rules the server enforces.

MODEL

Muse Spark

Chooses offers, chat steps, cart tools, photo matches and promotion drafts, using structured output against a server-built list.

MODELS

Muse Image · SAM 3.1

Muse Image draws banners and pair-deal pictures, labelled as AI-made. SAM 3.1 counts stock in a photo.

MODELS

Muse Wonder · Voice

Muse Wonder answers the owner through read-only tools. Muse Voice Transcribe gives the transcript and splits an order by speaker.

PAYMENT

PAID needs proof

Paid status comes only from a signed webhook or a server lookup.

DATA

Duplicates do nothing

A repeated webhook has no second effect. Row-level security keeps each shop apart.

EVIDENCE

A record and a fallback

Every model call is in an evidence ledger, and the shop keeps selling if the model is down.

SANDBOX ONLY

Where it stands.Plainly.

  • Deployed and running with the Muse Café demo shop and sample menu data.
  • Stripe sandbox only, with a US test merchant. No real money moves.
  • The Meta app is in development mode, so Messenger only answers accounts with a role on the app.
  • The physical card on Table 1 uses a plain link that can be copied. The NTAG 424 one-time check is built and tested with simulated taps.
  • Inside the Muse app, each purchase still asks for approval. The AI allowance applies to our Messenger chat and connector.
  • The BitPOS point of sale and BitPOS Mini existed before the hackathon. The provenance report separates old and new work.
